# Astra continuous research execution

Read `AGENTS.md`, `분석/기본기_연구/CURRENT.md`, and `분석/기본기_연구/ASTRA_START.md` first.

This is the primary TUI workflow. The fresh session is started by `scripts/cx1m` with model `gpt-6-astra`, high reasoning, a 1,000,000-token context window, a 900,000-token auto-compaction limit, and workspace-write. Do not use a resumed session as the research base.

This is a continuous research run. Consume the next prepared case from `data/기본기_연구/prepared_backlog/manifest.jsonl` in case ID order. The prepared backlog is a reservoir, not a request to stop after the cases currently named in CURRENT. When one case is complete, continue with the next prepared case while quota and an available source permit it. A completed batch, frontier, induction note, or progress report is not a normal termination condition.

For blind work, open only the manifest `blind_source` under `data/기본기_연구/prepared_backlog/blind_sources/`. Do not open `data/kice_questions.jsonl`, the candidate index, sealed answer/SDSS data, or existing explanations/code judgments until the blind raw records for every case in that `passage_group` are appended. Finish all group blind records before any answer_check for that group; then proceed group-wide through answer_check, independent code, and SDSS in order. Enforce `all_group_blind_records_before_any_group_answer_check`, then all group answer_check, all group independent_code (primary/auxiliary/surface plus 2–4 competitors), verify `all_group_independent_code_records_before_any_group_sdss_disclosure`, and only then disclose/compare SDSS. Never use one case's SDSS before another case in the same group has completed independent_code.

For every case preserve the existing sequence: blind official source reading and persistence, official answer check, code free logic, independent primary/secondary/surface code decision with 2–4 competitors, SDSS disclosure and comparison, then induction or boundary revision. Append each meaningful completed stage immediately to `data/기본기_연구/astra_handoff_queue.jsonl`. Keep the existing analysis depth: locations, minimal logic, intermediate inference, strongest distractor and exact error, code roles, competitors, confidence, boundary notes, and disagreement preservation.

At fresh start, and immediately before every new passage group, run `python3 scripts/meta_state.py` and use its output; do not rely on a stale file read. After appending any valid `meta_induction`, `manual_parity_audit`, or `depth_backfill` raw record, run the same sync and verify the resulting state before making the next control decision. Run it again immediately after a group-wide SDSS comparison completes.

Before starting a new passage group, sync state and apply this priority: (1) `manual_parity_audit_due=true` → Astra High audit first, then any explicitly requested depth_backfill and sync; (2) otherwise `meta_due=true` → Astra High cross-group `meta_induction`, append raw, sync and verify `meta_due=false`; (3) only when both are false, start the next passage group. Do not interrupt an in-progress atomic stage. The meta trigger is **3 groups** completed or **12 questions** completed since the last valid meta record. This is a semantic stage, not a summary: inspect strengthened boundaries (at least two cases and group provenance), explicit falsification attempts and rejected counterexamples, subtype candidates, primary/auxiliary revisions, unresolved boundaries, 1–3 structural next falsification targets, and reusable evaluation-item generation principles. Include all required fields: `window_groups`, `window_cases`, `strengthened_boundaries`, `falsification_attempts`, `revised_boundaries`, `subtype_candidates`, `primary_aux_revisions`, `unresolved_boundaries`, `next_falsification_targets`, `generation_principles`, `confidence`, `carryover_questions`.

After every third completed `meta_induction`, read the manual anchors (`코드심층_01/02/03`, `독립연구_03/04`, and 핵심8 기준) and perform a separate `manual_parity_audit`. If `manual_parity_audit_due=true`, perform this audit before starting any new passage group. Score the ten parity dimensions with concrete case IDs and add `depth_backfill` records for any semantic gap. Luna must only reflect these Astra records and never invent their judgments.

Do not read the sealed answer/SDSS file or existing explanations before the blind record for that case. Do not modify earlier first 풀이 or independent judgments. Luna owns formatting, CURRENT, processed state, audits, and mechanical backlog preparation; Astra owns semantic judgment.

Quota polling policy: run `scripts/codex_quota` at the indicated checkpoints. While both primary and weekly remaining values are above 15%, query after each passage group. When either value is 15% or lower but above 10%, query after each question or major stage. When primary remaining is 10% or lower, query after saving a completed atomic stage and before starting the next semantic stage; if that result is 7% or lower, hand off immediately, otherwise start at most the next atomic stage. When either value is first observed at or below 7%, enter normal handoff immediately. The helper reads `account/rateLimits/read` from `codex app-server --stdio` and emits machine-readable JSON; `quota_status=unavailable` is preserved without guessing and is not itself a handoff trigger.

When primary remaining or weekly remaining is first observed at or below 7%, do not start a new case, group, semantic stage, SDSS compare, induction, or boundary revision. Finish only the current safe atomic stage, append the raw record or a hold record immediately, perform the minimal `ASTRA_CHECKPOINT.md` persistence check, and hand off to Luna. After this observation no new semantic work is allowed.

At that threshold, use the actual `spawn_agent` tool with `model: "gpt-5.6-luna"`, `reasoning_effort: "medium"`, and no context fork (`fork_context: false`; no `fork_turns`). Pass only the handoff task and repository paths, not this Astra conversation. Luna must process unprocessed raw records, update the detailed artifacts, processed ledger, CURRENT, and backlog state, preserve holds and uncertainty, and avoid duplicate processing or new semantic judgments. Wait for the Luna result, then end the Astra session.

If runtime emits `less than 5% of your 5h limit left` or an equivalent primary usage-limit warning, immediately enter `EMERGENCY HANDOFF MODE`. This warning overrides the last helper result, `quota_status=unavailable`, prior quota values, and weekly remaining. After the warning, the only permitted actions are: append a minimal raw record only when the current atomic judgment is already substantively complete and only persistence remains; append one emergency checkpoint/hold record; spawn Luna; terminate Astra. If the current atomic stage still needs source reading, comparison, or reasoning, do not complete it; record it as incomplete/hold with the next needed work and blind/SDSS exposure state, then hand off. Do not call `scripts/codex_quota` again, wait for `/status`, read any new file/source/sealed data, run `rg`/`grep`/`find`, revisit documents, start any case/group/stage/blind/answer_check/independent_code/SDSS/induction/boundary/meta/audit/backlog work, or perform further semantic reasoning. The only path is `runtime warning -> completed raw or incomplete hold -> emergency checkpoint -> Luna spawn -> Astra termination`.

If the runtime reports no quota data, do not invent it. Continue using the policy above and preserve `quota_status=unavailable`; use the last successful value only as context, never as a fabricated current value. If Astra hits a hard limit before spawning Luna, the next `cxresearch` run must compare queue and processed first and run Luna recovery for pending raw before any new Astra semantic work. Stop normally only for quota safety, genuinely exhausted prepared backlog, an actual blocking error, or permission/system/safety inability to continue.
